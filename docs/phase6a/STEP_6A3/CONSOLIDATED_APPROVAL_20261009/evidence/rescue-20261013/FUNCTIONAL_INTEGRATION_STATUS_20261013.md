El mecanismo aprobado por el usuario es una **sustitución transaccional inmediata preservando ambas filas**: Subscription anterior con `ends_at` de corte y estado `ended`; nueva Subscription `active` desde el mismo instante, código único aportado por Platform Admin. Se aprobó una operación separada `POST /api/v1/platform/subscriptions/{id}:change-plan` y permiso `platform.subscription.change_plan` solo para Platform Admin. Para ejecutarla todavía se requiere publicar el payload/respuesta, ETag/`row_version`, códigos de auditoría/outbox, límites y elegibilidad de packs. Los packs pertenecen a una Subscription concreta; su traslado exige el binding de familia y límites comerciales, no una copia ciega. Cambiar `plan_version_id` in situ borraría la atribución comercial histórica y no es una salida aceptada.

Decisiones adicionales: traslado atómico solo de packs vigentes compatibles y rechazo completo si hay uno incompatible; coexistencia de múltiples ISO y leyes operativas para un tenant; suma sin retirar otros y reemplazo temporal de uno conservando historial/evidencia. El usuario prefirió un **catálogo y relación global de familia** frente a un atributo de texto en RegulatoryPack. Falta publicar el modelo exacto y los contratos ejecutables de elegibilidad/transporte. El usuario autorizó preparar, no activar, la propuesta [DRAFT_CANONICAL_AMENDMENT.md](../../../../../governance/amendments/COMMERCIAL_PACK_FAMILY_20261013/DRAFT_CANONICAL_AMENDMENT.md): `source_type` no identifica familia ISO. El borrador no modifica baseline ni PostgreSQL.

El esquema físico existente ya ofrece `starts_at`, `ends_at`, `cancelled_at`, `row_version`, FK a PlanVersion y UQ `(tenant_id, subscription_code)`. No se identifica DDL necesario para el cambio de plan **hasta que el contrato de transición esté aprobado**; no crear una migración especulativa. El `subscriptionCreate` actual bloquea segunda alta activa bajo lock del tenant. La UI ahora muestra estado y código de la suscripción vigente, oculta **Asignar plan** tras refrescar y explica el 409 sin prometer un cambio aún inexistente. También se corrigieron keys React duplicadas que podían retener el formulario durante el refresco.
