# STEP6A3 — QA session duration correction

Authority: explicit PO instruction, 2026-10-19; active master TCDX_GRC_MASTER_REGENT_BASELINE_v1.12_2026-10-16, rector45/46 DR003. Bounded correction under executable21 §2 and executable22 MI-006/007/012/015. No global closure or STEP6A4 authorization.

QA Keycloak already has SSO idle 1800s and absolute max 36000s, with client idle/max inheriting the realm; access tokens last 300s. Preserve those settings, MFA/password+OTP, cookie protections, grants and all canonical models. No Keycloak mutation is necessary. The application previously discarded provider refresh tokens and issued a nonrenewable TCDX JWT expiring after 300s.

For Managed Identity only, the backend retains the external refresh token in protected process memory alongside a digest of the currently issued TCDX token, its canonical principal and original verified authentication time. POST /auth/refresh accepts the current TCDX token as a renewal handle through Authorization: Bearer; it is not a domain operation or a new permission. Even after short access expiry, that exact handle may request renewal only inside the separately bounded idle/absolute session and while its original runtime revocation state remains unrevoked. Expired tokens remain forbidden on protected API operations. Unknown handles, missing/restarted state, expired idle/absolute sessions, disabled identities and revoked tokens fail closed. No offline tokens or external credentials reach the browser.

Each renewal requires the provider to accept its refresh grant and return a signature-verified ID token with the original issuer, subject, session ID, authentication time and password+OTP AMR proof. OpenID Connect Core §12.2 permits the refreshed ID token to omit nonce; if returned it must equal the original. The initial callback still requires the exact nonce. The canonical UserIdentity must still be active. Only then issue a new short TCDX JWT, audit audit.iam.application_token.issue.v1 / oidc.session.renew, revoke the previous jti and rotate the renewal handle. Concurrent requests share one exchange; replay of the old handle fails. Principal/session revocation during exchange/signing/audit wins. Access expiry is capped by the original absolute maximum. Transient provider failure does not clear the browser session or grant API access.

The optional signed session_renewable claim schedules renewal only; it grants no authority. BrowserSession renews on API demand near access expiry (remaining quarter of the signed lifetime), preserving selected tenant, with a single in-flight request. It never retries arbitrary 401 responses or resurrects a cleared/new session. Background timers do not extend idle sessions. Zoho sessions keep their existing behavior. Normal logout revokes the current jti and clears tab-scoped credentials. Existing cookies and visual presentation are unchanged.

Deployment is QA only, activated by APP_SESSION_IDLE_SECONDS and APP_SESSION_MAX_SECONDS; exact approved QA values live in deploy/qa/session-duration.json, derived from the observed realm. No production, schema, roles/permissions, tenant model, domain lifecycle or infrastructure topology changes. Verification is limited to authentication/renewal/bounds/revocation, builds and required integrity. Real 30-minute runtime evidence and human functional acceptance remain distinct from accelerated clock tests.
